# Weekly Rank Tracking

## Objective
On a weekly schedule (default Monday 08:00 in `TIMEZONE`), check where `TARGET_DOMAIN` ranks in Google organic results (top `MAX_RESULTS`, default 100) for every keyword in the tracker sheet, in each configured market. Write the positions into the wide-format tracker and email a summary showing what improved and what dropped.

## Inputs
| What | Where |
|---|---|
| **Keywords** | The tracker tab itself. Every row with a keyword in **column B** and a volume in **column C** is tracked. Column A is the target page URL. To add or remove a keyword, edit the sheet; no code change is needed. |
| Target domain | `.env` → `TARGET_DOMAIN` (subdomains count too) |
| Markets | `.env` → `MARKETS`, e.g. `UK,US`, in the same order as the sheet's columns. Custom markets: `CODE=google_domain:country:locale`. |
| Oxylabs Web API key | `.env` → `OXYLABS_API_KEY` |
| Google OAuth client | `credentials.json` (Desktop app client from Google Cloud Console) |
| Google OAuth token (Sheets + Gmail send) | `token.json`, generated by `tools/google_auth.py` |
| Sheet ID | `.env` → `GOOGLE_SHEET_ID` |
| Tracker tab name | `.env` → `TRACKER_TAB` (optional, default `Tracker`) |
| Report recipient | `.env` → `REPORT_EMAIL_TO` |
| Run date, schedule, header date format, email subject | `.env` → `TIMEZONE`, `SCHEDULE_CRON`, `DATE_FORMAT`, `REPORT_SUBJECT` |
| Search depth | `.env` → `MAX_RESULTS` (default 100 organic results) and `MAX_PAGES` (hard cap, default 15 pages) |

All checks use desktop results.

## Tools
| Script | Purpose |
|---|---|
| `tools/rank_tracker.py` | Core job: read keywords from the sheet → Oxylabs SERP → write a new date column group → send email. Flags: `--no-sheet`, `--no-email`, `--markets UK US`, `--list-keywords`, `--repair`. |
| `tools/import_tracker.py` | Copy a tab from another spreadsheet in as the tracker tab (`--tab`, `--keep-rows`). One-off. |
| `tools/google_auth.py` | Browser OAuth; writes `token.json`. |
| `tools/push_modal_secret.py` | Pushes `.env` + `token.json` into the Modal secret (`MODAL_SECRET_NAME`, default the app name). |
| `tools/modal_app.py` | Modal app with the weekly cron (timeout 2h). |
| `tools/scan_secrets.py` | Checks the repo for keys, IDs, emails and local paths before you share it. |

## One-time setup
1. Install Python 3.11+ and run `pip install -r requirements.txt`.
2. **Google Cloud:** create a project, enable the **Google Sheets API** and **Gmail API**, then create an OAuth client of type *Desktop app* and save it as `credentials.json` in the project root.
3. **OAuth consent screen:** add the sending Gmail account under **Test users**, or sign-in fails with `Error 403: access_denied`. While the app stays in **Testing** mode, Google expires the token after 7 days (see "Weekly re-auth" below). Publishing the app ("In production") removes that limit.
4. `python tools/google_auth.py`: sign in with the Gmail account that should send the report and can edit the sheet.
5. Copy `.env.example` to `.env` and fill in at least `TARGET_DOMAIN`, `OXYLABS_API_KEY`, `GOOGLE_SHEET_ID`, `REPORT_EMAIL_TO` and `MARKETS`. Set up the tracker tab from `templates/tracker_template.csv`, or import an existing one with `import_tracker.py`.
6. `python tools/rank_tracker.py --list-keywords` to check what will be tracked (free).
7. Test locally (uses Oxylabs credits): `SAVE_RAW=1 python tools/rank_tracker.py --no-email` (PowerShell: `$env:SAVE_RAW='1'; python tools/rank_tracker.py --no-email`).
8. `modal setup`, then `python tools/push_modal_secret.py`, then `python -m modal deploy tools/modal_app.py`.

## Output
**Tracker tab** (wide format): each run adds a column group to the right of the last used column, with one column per market. Row 1 gets the date (`DATE_FORMAT`), row 2 gets the market codes, and each keyword row gets its positions.
- Position is the organic rank counted across pages (ads, AI Overviews, and other SERP features are excluded). `-` means not in the top `MAX_RESULTS`. `ERROR` means the lookup failed. Google returns about 8–10 organic results per page, so reaching 100 takes about 11–12 pages.
- Each position cell has a **note with the ranking URL**. Compare it with column A (the target page) to spot the wrong page ranking.

**Email**: one table with every keyword, showing each market's position, the change since the previous column group (`+3` = up 3, `entered`, `dropped out`), and positions linked to the ranking page. It attaches `<domain>_rank_tracker_YYYY-MM-DD.csv` with the full tracker. CSV is used because attaching the native Sheet would need an extra Drive scope and a new sign-in.

## Cost
Searches per run = keywords × markets, 3 in parallel (`MAX_WORKERS`). Each search fetches one page at a time and stops as soon as the domain is found or `MAX_RESULTS` organic results have been checked. A keyword ranking at #N costs about ⌈N/9⌉ requests, and one not in the top 100 costs about 11–12. The hard cap is searches × `MAX_PAGES`. For example, 30 keywords × 2 markets is roughly 150–350 Oxylabs requests a week and takes 20–40 minutes.

## Weekly re-auth (only while the OAuth app is in Testing)
Before each scheduled run:
```
python tools/google_auth.py          # browser sign-in
python tools/push_modal_secret.py    # send the new token to Modal
```
If you skip it, the job fails with `invalid_grant`. Because the email also uses this token, **no report or error email arrives**. A missing weekly email means the token has expired.
To get rid of this chore, publish the consent screen, or switch to a service account for Sheets and a Gmail App Password (SMTP) for email.

## Edge cases & behaviour
- **One lookup fails** (Oxylabs error or timeout): that cell gets `ERROR` (the error text is in the email cell's hover title). The other lookups still run and the email still goes out. **Fix it with `python tools/rank_tracker.py --repair`.** This re-checks only the `ERROR` cells in the latest column group, rewrites that group in place (no new column) and re-sends the email. It costs Oxylabs requests only for the failed cells.
- **Run crashed after writing the sheet but before the email** (the email didn't arrive, but the new column exists): run `--repair`. If there are no `ERROR` cells it scrapes nothing and just rebuilds the email from the sheet and sends it. Don't do a normal rerun, because that would add a duplicate column group.
- **429/5xx from Oxylabs**: retried 8× with backoff (15s, 30s, … capped at 90s).
- **Response shape**: the parser searches the response for an `organic` / `organic_results` list and reads `url` (or `link`) from each item. If Oxylabs changes the format, the run fails with the top-level keys listed in the error. Re-run locally with `SAVE_RAW=1` and inspect `.tmp/`.
- **Messy history values** like `37/blog` or `9, O`: the leading number is used when working out the change. Blank values mean "no comparison".
- **Notes or text to the right of the data**: the new columns go after the *widest* row, so a note far to the right pushes the next columns out past it.
- **Changing the market list**: the change column compares with the previous group by position, so keep existing markets in the same order and add new ones at the end. Groups are found by the first market's code in row 2.
- **Token revoked or expired** (`invalid_grant`): re-run `google_auth.py`, then `push_modal_secret.py`. No redeploy is needed.
- **Changing code, schedule or app name**: `python -m modal deploy tools/modal_app.py`.
- **Changing other .env values**: run `push_modal_secret.py` (no redeploy needed).

## Learnings log
- Oxylabs' current API is `POST https://webapi.oxylabs.io/v1/scrape/google/search` with Bearer key auth and params `query`, `domain`, `location` (2-letter country), `locale`, `start_page`, `pages`, `output: ["json"]`. The older `realtime.oxylabs.io/v1/queries` + `source: google_search` + `geo_location` + `parse` format is not in the current docs. Docs recommend a client timeout of at least 150s. Docs: https://developers.oxylabs.io/products/web-api
- The response envelope uses `state: "done"`, not `status`. Organic results are at `results[0].json.results.organic[]` with `pos` (per page), `pos_overall` (counts SERP features too), `url`, `title`, `desc`. Other sections are `paid`, `ai_overviews`, `organic_videos`, `related_questions`, `related_searches`, `images`. `json.last_visible_page` gives the SERP depth. Expect 8–10 organic results per page. Ads (`paid`) are deliberately not counted as rankings.
- With 6 searches in parallel, US searches failed with `500 REQUEST_FAILED_AFTER_TOO_MANY_RETRIES` (`state: faulted`, not billed). The fix was longer retry backoff and at most 3 searches in parallel.
- Oxylabs faults cluster on low-volume queries, not only on the US, so retries were raised to 8.
- An email-building crash after the sheet write (an int position passed to `html.escape`) led to `--repair`, which recovers without re-scraping.
- Positions from a fresh, non-personalised SERP API are often lower than numbers checked by hand in a browser, where location and personalisation skew results. When you switch an existing tracker to this tool, expect a one-time step in the history. It comes from the change of method, not a real drop.
